## Scope

Expand the exact special parameter `$?` to the previous completed command status:

```sh
cat /missing; printf 'status=%s\n' "$?"
cat /system/welcome.txt | wc -l; echo $?
. /system/tests/03-errors.sh || printf 'script=%s\n' "$?"
```

Support unquoted/double-quoted occurrences and concatenation such as `code=$?`.
Single-quoted or escaped dollars remain literal. Do not recognize a parameter
across quote/escape boundaries: `$"?"` is not `$?`. Preserve existing glob quote
masks, including literal versus wildcard question marks when no expansion occurs.
Apply the same word transformation to argv, command names, dot operands and
redirection paths, before existing filename expansion and command dispatch.

Only bare `$?` is added. `${?}`, other parameters/variables, assignments,
substitution, arithmetic, field splitting, IFS, export and environment handling
remain outside this slice. Preserve other currently accepted word bytes and
their existing semantics; do not silently implement a wider parameter language.
Unquoted `${?}` keeps its current unsupported grammar behavior; quoted `${?}`
is not newly interpreted. No process-exit status, numeric exit operands, kernel
pipefail policy, execution packages, syscall or capability changes are included.

## Generated word ownership

Keep the existing main EBNF/generated lexer/parser authoritative for shell tokens,
word boundaries, operators and command ASTs. Do not change its accepted language
to make this feature work. Introduce a focused word-parts EBNF under apps/shell,
generated by the repository-local published MaiaCC into JS and C++98 frontends.
Its input is exactly one accepted main-frontend word terminal, not the entire
command line. It identifies literal/quoted/escaped parts and status parameters.

The semantic renderer consumes those generated nodes, removes quotes/escapes,
replaces only status nodes and emits bytes/protection masks for existing MaiaGlob.
Do not add a handwritten word lexer/parser or search/replace raw command strings.
The generated word frontend replaces the current quote-decoding loop within
this bounded responsibility; the collector must not duplicate its grammar.

Use deterministic generated identifier prefixing, following the existing
MaiaGlob integration pattern, to combine frontends in the C++98 translation
unit. Version the EBNF, generated JS/C++/XML/prefix artifacts and reproducible
generation/build commands. Never hand-edit generated files. Validate JS word
trees first, then C++98 raw-input trees/renderer and actual WASM execution.

## Status lifetime and evaluation order

- Initialize a persistent shell last-status value to zero at startup. Keep it
  separate from the current unit's accumulating failure and list-selection state.
- Capture one incoming status for each selected unit before any of its words
  expand. All argv/redirect words and all stages of that pipeline see the same
  captured value. Do not let expanding/dispatching an earlier word change it.
- Update the persistent value only after a unit fully completes: queued output
  drains, owned handles close and the existing kernel completion packet is reaped.
  Keep the existing status mapping: success0, operational1, usage/expansion2,
  unknown-command127, or existing kernel pipeline completion status. Render the
  existing unsigned 32-bit value as decimal without changing kernel authority.
- Skipped AND-OR units and blank/comment-only input leave the value unchanged.
  A rejected physical input line (lexical/syntax/static bounds) or terminal input
  overflow sets it to2 without executing a valid prefix. Ordinary command failure
  continues to obey existing list/script selection rules.
- Keep status across physical terminal lines and script lines. A dot body begins
  with its caller's incoming status, not an artificial successful load status.
  Blank/comment lines preserve the last executed body status. Empty dot returns0
  under the approved existing contract; nonempty dot returns its final unit status,
  with existing load/abort failures overriding it. The completed dot status becomes
  the caller's last status before selecting/expanding its suffix.
- Caller reconstruction after dot must only parse/validate immutable syntax;
  it must not expand parameters or overwrite the returned status. Do not rerun
  previously executed caller units or eagerly expand remaining ones.

For example, after a failure, `printf '%s %s\n' "$?" "$?"` uses the same failure
twice and then completes successfully. A following `echo $?` consequently prints0.
No extra stdout/stderr formatting is performed by the host or I/O guest.

## Static validation, bounds and asynchronous behavior

Separate status-independent word validation from selected-unit rendering. Existing
whole-line structural/static rejection must remain before any effect; preflight
must not evaluate `$?` using a speculative status or change status state.
At execution, decimal insertion can enlarge a word: enforce the existing95-byte
decoded-word limit after rendering, before glob enumeration/redirect opens/worker
launch. Overflow is a normal unit failure2, not an internal fatal invariant.
Retain earlier completed units' effects and apply the existing AND-OR rules.

Keep255-byte physical input,32 main tokens,1024 main-tree nodes,eight list units,
twelve expanded words and existing script/pipeline bounds. The auxiliary word
frontend has fixed storage: at most256 tokens and2048 nodes for one at-most255-byte
raw word; reuse scratch storage across words rather than copying entire command
trees. Record exact validated bounds and reject exhaustion without truncation.
Keep the shell's32-page/four-handle manifest unchanged; measure actual memory,
stack, repeated-word parsing and scheduler progress. No recursive expansion,
unbounded allocation or busy waits are introduced.

### Toolchain boundary encountered

The first build rejected direct global POD member access (`gShellWordTree.overflow`):
MaiaC reports "Struct member access is currently supported only for frame-backed
locals and parameters". At that checkpoint, production used local pointer views of the same static
collector/node storage, following existing shell/Glob patterns. Native and WASM
behavior passes through the required compiler chain; no generator/compiler was
edited and this is not evidence that direct global struct members are supported.
That compiler coverage limitation remains separate follow-up work requiring its
owner-repository authorization. Initial grammar drafting also used CharCode in
syntax productions; corrected the source to named lexical tokens as the existing
MaiaCC grammar requires, then regenerated. No generated file was hand-edited.

Interactive browser, MaiaWASMVM/device, new kernel/I/O builds and native kernel
policy/sanitizer gates were not rerun. No wider POSIX/parameter conformance claim.
main remains b13f168 with prior dirty work/staged pins preserved. No commit/push,
npm/version or history operations. Remaining work includes other variables,
parameter forms, compound execution, extended dot/sh semantics and device/runtime
conformance under their concrete contracts.
