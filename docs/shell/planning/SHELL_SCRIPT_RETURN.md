## User-visible scope

Add `return` and `return n` only while executing the body of the one active dot
script. A successful return stops that script immediately after its selected
command completes cleanup and resumes its saved caller. It preserves variables,
cwd and completed VFS effects,as existing dot does. It does not exit the shell.
For example,the following file returns7 without printing its last line:

```sh
echo before
if true; then return 7; fi
echo NEVER
```

The caller can select a recovery branch with `. /tmp/example.sh || echo $?`.
`return` without an operand uses the preceding completed status visible to the
selected unit,after branch/list selection and before its expansion/dispatch.
Explicit n is an unsigned ASCII decimal integer0..255; leading zeros are decimal
(`007` is7). Accept only zero or one expanded operand. Signs,hex/octal notation,
`--`,empty strings,values above255 and extra operands are outside this profile.
No modulo reduction,options,functions,positional arguments or nested dot support.

An invalid operand/arity or return outside a dot body reports one bounded normal
stderr diagnostic and command status2 without returning,terminating the shell or
corrupting caller state. This includes the terminal and terminal-owned loops.
Subsequent AND-OR/list/script selection follows existing non-errexit rules.
These bounded error rules are explicit project choices: invalid return arguments
already differ substantially between installed dash and Bash. Do not claim
agreement on excluded/error cases or full POSIX special-builtin semantics.

Selected return may occur in an existing script foreground list,if condition or
branch,loop condition/body or the one optionally negated inner if. It leaves the
entire current script,not merely the loop. Skipped return performs no expansion,
file access or request. Whole-unit syntax/quota preflight still applies before
effects. A dynamic command name produced by normal existing expansion follows
the same dispatch/context validation. Return is not a pipeline worker; the fixed
cat/final-wc pipeline command whitelist remains unchanged.

## Requested status and negation

A requested nonzero result is a successful control operation. Keep that result
separate from raw expansion/dispatch/redirect/close/drain success. `return 7`
must not be canceled just because7 is nonzero.

Successful script return abandons the current script unit's `!` and all unfinished
script if/loop joins. In particular,`! return 7` returns7,and a return inside a
negated if/loop also returns7. It does not consume the loop-control aggregate
inversion rule: break/continue remain unchanged. No branch/body/loop remainder,
no-match zero or abandoned join may run after the successful return.

After returning,the independently saved dot caller completes normally. A `!`
on that dot invocation,or a subsequently completed caller aggregate,applies at
its own existing completion point. Thus `! . file` with requested script result7
completes0;requested script result0 completes1. Preserve generated caller PC,
unit negation,for frozen values/index,conditional phase/count/last-body status
and inner-if prefix certification without replay or cross-script loop control.

Invalid preparation/operand/open/close/drain cancels the request before any
transfer. Complete that failed command through ordinary unit negation and script
joins exactly as today; a resulting0 from `!` cannot resurrect the request.
Preserve diagnostics,partial file effects and backpressure. A redirection open
failure does not arm return; a close failure after arm cancels it. Exit/fatal
shutdown clears pending return and uses the existing shutdown policy.

## Generated syntax and bounded completion

Keep main/word/test grammars and generated frontends unchanged. Add one tiny
private operand grammar,generated by MaiaCC/tREx in JavaScript and C++98:

```ebnf
Input ::= Status? EOF
Status ::= DECIMAL
<?TOKENS?>
EOF ::= $
DECIMAL ::= [0-9]+ #x0
```

Frame only an already expanded optional argv value with a NUL terminator; no
source reconstruction,host number parsing or handwritten numeric lexer/parser.
Zero operands produce only EOF. Generated DECIMAL classification owns spelling;
semantic accumulation checks the0..255 range before multiplication/addition.
Use at most96transport bytes,2tokens and8tree nodes,with exact guards and failure
cleanup. Reject arity before framing; do not truncate or wrap long values.
Generate identifier prefix/unprefix transport by the established helper pattern,
without editing generated output. A generator/compiler defect requires a minimal
reproduction and a separate owner decision before changes outside this scope.

Use one fixed private pending-return request certified to the active script and
selected EXEC origin PC/unit. It owns a requested status0..255 and an explicit
active flag;0 is a valid requested status,not an inactive sentinel. Validate
phase,script position,flow bounds,origin and the existing loop/region identities
before transfer. Reject stale/corrupt/caller-owned requests; return and loop
control requests cannot both be active. No dynamic stack,recursive evaluator,
second AST,synthetic command or arbitrary jump is introduced.

The terminal command-finishing path retains its raw failure result until drain
and owned handles close. Only then may it consume a validated return,discard the
script plan/frames and invoke the existing generated caller reconstruction once
with the requested result. Ordinary completion keeps its present unit/aggregate
negation logic. Do not publish an intermediate success,step another script line
or borrow the terminal stream before the return finishes. Requests clear on
normal consumption,cancellation,new unit,script load/return and fatal/exit.

Retain the16-step guest quantum,32-op dispatcher,8leaves/32flow instructions,
32main tokens/1024nodes,255input bytes,95byte words/12argv,32variables,one active
16KiB/256physical-line script,for12values,conditional12bodies/13conditions,
four shell file handles and32/8page shell/I/O budgets. The new tiny frontend and
fixed request must fit these existing memory limits;measure actual consumption.
No multiline input or broader compound nesting is authorized.
